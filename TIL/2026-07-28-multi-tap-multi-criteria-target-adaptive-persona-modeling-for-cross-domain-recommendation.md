## Multi-TAP : 교차 도메인 추천(CDR) 성능을 높이기 위해 제안된 최신 프레임워크 


### 핵심 개념 및 배경

- 도메인 내 이질성(Intra-Domain Heterogenity) 해결 : 기존 방법들은 사용자 선호도가 단일하다고 가정하여 정보를 압축하지만, 실제로는 가격 민감도나 카테고리 선호 등 여러 소비의도가 공존한다는 점에서 착안
- 대형 언어 모델(LLM) 활용 : 사용자 행동과 아이템 메타데이터(가격, 인지도, 평점 등)를 바탕으로 다양한 선호 기준을 반영하는 자연어 페르소나 설명을 생성

## 주요 단계 

1. 다중 기준 페르소나 모델링
- 각 도메인 내에서 사용자의 세분화된 소비 의도와 선호 기준을 자연어 페르소나로 구축
- Self-Attention을 통해 기준별 페르소나 임베딩 집계
1. 타겟 적응형 전송
- 소스 도메인의 모든 정보를 무분별하게 옮기지 않고, 타겟 도메인과 연관된 페르소나만 선택적으로 전송
- 타겟 도메인의 특성과 관련성을 보존하며 지식을 공유

## Motivation : IDH (Intra-domain heterogeneity)


⇒ 하나의 동일한 데이터 영역이나 시스템 내부에서, 데이터의 분포·사용자 선호도·맥락 등이 균일하지 않고 서로 다르게 나타나는 현상

# 📌 연구 주제


**Multi-TAP: Multi-criteria Target Adaptive Persona Modeling for Cross-Domain Recommendation**


(다중 기준 기반 타겟 적응형 페르소나 모델링을 통한 크로스 도메인 추천)


---


## 1. 배경 — 기존 크로스 도메인 추천(CDR)의 한계

- **Cross-Domain Recommendation (CDR)**: 소스 도메인(source domain)에서의 사용자 선호를 타겟 도메인(target domain)으로 전이(transfer)해 추천 성능을 높이는 태스크
- **문제점**: 기존 방법들은 소스 도메인의 모든 상호작용/아이템 정보를 **하나의 통합된 사용자 임베딩**으로 뭉뚱그림
    - 이 과정에서 타겟 도메인과 관련 없는(혹은 불필요한) 정보까지 함께 반영되어 **추천 성능이 오히려 저하**될 수 있음

---


## 2. 동기 — 소비자는 다기준(Multi-criteria)으로 아이템을 평가한다

- 소비자가 제품을 구매할 때는 하나의 기준이 아니라 **다양한 관점**에서 아이템을 판단함
    - **가격(price)**, **인기도(popularity)**, **평점/신뢰도(rating)** 등
- 이걸 모두 하나의 뭉뚱그려진 선호도로만 표현하는 건 부적절함

### 검증 실험 — 선호도는 카테고리별로도 다르다

- 가격 선호 수준을 5분위(quintile)로 나눠서, 한 카테고리에서의 선호 수준이 다른 카테고리에서도 유지되는지 측정
- **결과**: 약 **30% 정도만 보존** → 대다수 사용자는 카테고리마다 서로 다른 선호 수준(가격 민감도 등)을 가짐
- **시사점**: 같은 도메인 내에서도 사용자 선호는 **이질적(heterogeneous)** → 어떤 정보를 무엇을 기준으로 전이할지 먼저 고민이 필요

---


## 3. 연구 목표

1. **단일 도메인 내에서도 존재하는 사용자 선호의 이질성**을 잘 포착하는 다기준 사용자 페르소나 구축
2. 이렇게 만든 페르소나를 **크로스 도메인 추천에 효과적으로 활용**

---


## 4. 제안 프레임워크 — Multi-TAP 개요


### Step 0. 메타데이터 전처리

- 가격, 평점, 인기도(리뷰 수 등) 정보를 활용
- 각 아이템이 **자신이 속한 카테고리 내에서 상대적으로 어느 수준(예: High/Medium/Low)**에 위치하는지 레벨로 변환 (binning)
    - 예: "가격은 High, 평점은 Medium"

### Step 1. 페르소나 베이스 구축 (LLM 활용)

- 일반화 가능한 정보(가격/평점/카테고리)를 기반으로, LLM을 통해 사용자별 **5가지 기준에 대한 페르소나 설명(persona description)** 생성
    - 예: 가격 페르소나, 인기도 페르소나, 평점(신뢰도) 페르소나 등

### Step 2. 페르소나 임베딩(Persona Embedding) 생성

- 생성된 페르소나 설명들을 임베딩으로 인코딩

### Step 3. 도메인 간 연결 — "도플갱어(Doppelganger)" 중간 임베딩

- 소스 도메인 페르소나와 타겟 도메인 페르소나를 **직접 정렬(align)** 하지 않고, 중간에 **도플갱어 임베딩**을 두어 간접적으로 연결
- **Contrastive Learning (InfoNCE Loss)** 활용
    - 같은 사용자의 임베딩끼리는 가깝게
    - 다른 사용자의 임베딩끼리는 멀게

### Step 4. 최종 추천

- 백본(backbone) 추천 모델 + 페르소나 임베딩을 결합
- 가벼운 모델(경량 모델)을 활용해 사용자-아이템 상호작용과 페르소나 정보를 함께 반영한 추천 점수 산출
- **손실 함수**: 추천에서 흔히 쓰이는 **BPR(Bayesian Personalized Ranking) 계열의 pairwise ranking loss** 사용 (직관: 관련 있는 아이템의 점수를 관련 없는 아이템보다 높게)

---


## 5. 실험


### 실험 설정

- 여러 도메인 페어(예: 전자제품 ↔ 스포츠 등)에서 크로스 도메인 추천 성능 검증
- 5개 CDR 베이스라인 + 싱글 도메인 베이스라인과 비교

### 주요 결과

1. **전반적인 추천 성능**
    - 대부분의 도메인 페어에서 베이스라인 대비 우수한 성능
    - 단, 한쪽 방향(예: A→B)에서는 성능이 다소 떨어지고, 반대 방향(B→A)에서는 더 큰 성능 향상을 보이는 **비대칭적 결과**도 관찰됨
2. **페르소나 생성 방식의 효과 (Ablation)**
    - (a) 페르소나 없이 원본 데이터만 전달 vs (b) 메타데이터 전처리만 적용 vs (c) 제안한 전체 페르소나 파이프라인 비교
    - 제안한 방식(전체 페르소나 파이프라인)이 가장 좋은 성능
3. **백본 모델 강건성(Robustness)**
    - 어떤 백본 모델을 쓰든 관계없이 **안정적인 성능** 유지
4. **효율성(Efficiency)**
    - 백본 모델 자체의 추가 연산 부담이 크지 않음
    - 전체적으로 **시간/비용 측면에서도 저렴**하게 수행 가능

---


## 6. 결론

- 동일 도메인 내에서도 사용자 선호의 이질성(heterogeneity)이 존재하며, 이를 포착하는 것이 추천 성능 향상으로 이어짐을 확인
- 크로스 도메인 추천에서 "무엇을 전이할 것인가", "어떻게 전이할 것인가"에 대한 새로운 접근(다기준 페르소나 + 도플갱어 임베딩)을 제시
- 이를 통해 보다 개인화되고 해석 가능한 크로스 도메인 추천 시스템 방향을 제안
